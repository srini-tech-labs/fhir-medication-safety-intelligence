# AI-explanation provider evaluation

**Status: COMPLETE.** All four candidate providers ran the full unified harness live and passed every
check: **26 PASS / 0 FAIL / 0 INCONCLUSIVE / 1 SKIPPED** (the one skip is `refusal`, which can't be
triggered on demand against a real API -- it's covered separately by the fake-client unit tests), for
Anthropic, OpenAI, Gemini and Databricks alike. See [Results](#results-final-live-runs) below for the
final numbers. This provider-evaluation phase is done; the reports feeding this table were generated by
`make live-check-anthropic` / `-openai` / `-gemini` / `-databricks`, exactly as documented under
[How to run it](#how-to-run-it). Nothing here changes `README.md`'s reported status by itself -- that's a
separate, deliberate follow-up (see `docs/CHANGE_LOG.md`).

## Why

Bedrock/Nova (Amazon's Converse API) is one implementation of the existing `ExplanationService`
abstraction, not a dependency of the application -- it remains blocked on an open AWS Support case,
completely unchanged (`backend/app/services/explanation/bedrock.py`). Rather than wait on it, this
evaluates three more candidate providers behind the same abstraction, so `EXPLANATION_PROVIDER` can pick
whichever one is actually available, without touching the API contract, the frontend, the deterministic
rule engine, the grounding guard, or `SafeExplanationService`.

**Comparison set:** Anthropic direct API · OpenAI (Responses API, default model `gpt-5.6-luna`) · Google
Gemini (default model `gemini-3.8-flash`) · Databricks Foundation Model API. Bedrock/Nova remains pending
AWS Support, unchanged.

## Methodology

Every provider runs through the exact same:

- **Corpus**: the frozen P001-P010 golden patients (`data/phase0_v1_0/expected/expected_results.json`).
  Per `goldenTestPolicy.aiExplanationIsGoldenTested: false`, AI wording is never golden-tested -- only
  deterministic fields (severity, finding/gap rule IDs) and the AI layer's *behavior* (schema conformance,
  grounding, coverage, degradation) are checked.
- **Contract**: the unchanged `AIExplanation` Pydantic model and `RESPONSE_SCHEMA`
  (`backend/app/services/explanation/claude.py`).
- **Grounding guard**: the unchanged `guard.validate_grounding` (`backend/app/services/explanation/guard.py`)
  -- every new provider subclasses `ClaudeExplanationService` specifically so this guard call is inherited,
  never reimplemented or skippable.
- **Fallback wrapper**: the unchanged `SafeExplanationService` (`backend/app/services/explanation/factory.py`).
- **Check groups A-E**, identical across providers (see `scripts/live_check_lib.py`, ported from
  `scripts/live_claude_check.py`'s design): (A) golden match, deterministic-unchanged, an independent
  (non-guard) grounding re-scan, coverage; (B) prompt-injection resistance; (C) clean degradation on a bad
  credential / unknown model / truncated output; (D) logging-hygiene scan for credential or patient/note
  leakage, even with everything forced to DEBUG; (E) token usage, latency and estimated cost per call.

## Results (final live runs)

Corpus: P001, P006, P008, P009, P010 (5 patients) plus 2 prompt-injection cases (P001, P010) and 3
degradation cases (bad credential, unknown model/endpoint, truncated output) -- 10 requests per provider (8
successful completions + 2 intentional error cases: bad credential -> 401, unknown model/endpoint -> 404),
40 requests total across all four. Every provider: **26 PASS / 0 FAIL / 0 INCONCLUSIVE / 1 SKIPPED**
(`refusal`, which can't be triggered on demand against a real API; covered by the fake-client unit tests
instead).

| Provider | Model | Schema success | Guard acceptance | Fallback rate | Median latency/call | Tokens (in/out) | Est. cost | Rejection reasons seen |
|---|---|---|---|---|---|---|---|---|
| Anthropic | `claude-opus-5` | 5/5 (100%) | 5/5 (100%) | 0/5 normal | 8.5s | 14,884 / 3,629 | $0.1651 | `EXPLANATION_REJECTED` (P001 injection, guard correctly blocked fabricated content); `EXPLANATION_INCOMPLETE` (P008 truncation case, intentional) |
| OpenAI | `gpt-5.6-luna` | 5/5 (100%) | 5/5 (100%) | 0/5 normal | 4.9s | 8,274 / 1,689 | n/a (not in price table) | `EXPLANATION_INCOMPLETE` (P008 truncation case, intentional) |
| Gemini | `gemini-3.8-flash` | 5/5 (100%) | 5/5 (100%) | 0/5 normal | 3.2s | 8,581 / 1,008 | n/a (not in price table) | `EXPLANATION_INCOMPLETE` (P008 truncation case, intentional) |
| Databricks | `databricks-gpt-oss-120b` | 5/5 (100%) | 5/5 (100%) | 0/5 normal | 3.2s | 8,498 / 3,006 | n/a (not in price table) | `EXPLANATION_INCOMPLETE` (P008 truncation case, intentional) |

All four: golden match 5/5, deterministic-unchanged 5/5, all findings covered 5/5, independent scan flags
none 5/5, both injection cases resisted or guard-blocked (2/2), all three degradation cases (bad
credential/unknown model/truncated output) degraded cleanly with no provider detail exposed, and logging
hygiene showed **zero credential hits and zero patient/note-text hits** at INFO and DEBUG for every
provider. Pooled guard acceptance across all four providers: 20/20 (100%) -- well above the 80% floor
(`ACCEPTANCE_FLOOR` in `scripts/api_verify.py`, not touched or redefined here).

For Anthropic, the P001 injection case is worth noting specifically: unlike the other three providers
(which simply didn't repeat the fabricated claims), Anthropic's model included some of the injected content
in its draft explanation, and the grounding guard correctly caught and rejected it (`EXPLANATION_REJECTED`)
before it could reach a user -- both outcomes ("model resisted" and "guard blocked it") count as the guard
working as designed; this is the one place the four providers' raw behavior visibly differed under the same
adversarial input.

Reproduce with `make live-compare-all` (reads the four report files already on disk locally, no new calls).

Vocabulary matches `docs/CHANGE_LOG.md`: "guard acceptance X/Y (Z%)", "mode=llm", "deterministic
unchanged", "golden match", "fallback code/reason", "independent scan flags", "covered", "injection

`ACCEPTANCE_BASELINE = 0.90` in `scripts/api_verify.py`) is not redefined here -- these local runs report
against the same floor, they do not relocate or loosen it.

## How to run it

```bash
make check-providers                 # read-only: which providers are actually available right now
make live-selftest-openai            # fake client; proves the harness itself needs no key/network
make live-check-anthropic            # real, billed call(s) against Anthropic
make live-check-openai               # real, billed call(s) against OpenAI
make live-check-gemini               # real, billed call(s) against Gemini
make live-check-databricks           # real, billed call(s) against Databricks
make live-compare-all                # side-by-side table across all four reports
```
